# YallaFlow — Projects Page UX Improvement (brief from the owner, 2026-11-17)

Goal: transform the Projects page from a statistics-heavy dashboard into a clean, modern, actionable project overview. In 5 seconds a user should understand: (1) current state of each project, (2) what work is open or running, (3) whether anything needs the user's attention, (4) the next useful action. Focused UX improvement, not a Console redesign.

1. Review existing implementation (viewProjects, stats/progress, health, work items, agent activity, approvals, navigation/actions, styles, RTL/LTR). Identify misleading values. Do not invent states, progress values or next actions.
2. Cards: name+path; selected-project indication; readiness/health separate from execution state; open and completed counts; current work item when available; last activity; relevant next action; attention indicators only when meaningful. Remove the five unlabeled mini charts (keep workflow detail inside the project). Remove/replace the unclear circular percentage; any remaining percentage must have explicit, accurate scope. Consistent headers/spacing. Cards clickable to open the project; inner controls independently usable.
3. Context-aware next action derived from real state (examples: needs understanding -> Start Project Understanding; setup -> Continue Setup; pending approval -> Review Decision; running agent -> View Running Work; open task -> Continue/Open Task; done/idle -> Open Project or Add Work). Not a fixed order. Never mark blocked/running/ready without evidence. No duplicate actions.
4. Agents & Needs You: no large empty agent panel; concise activity when an agent is running; prominent pending approvals/blockers; empty Needs You collapses to a small indicator; review decision/approval navigation; memory-review counts understandable and navigable where a supported destination exists. Don't hide meaningful warnings.
5. Actions: Open Project primary; three-dot menu with Open Folder, Copy Path, Remove Project. Removal keeps existing safeguards and confirmation. Accessibility and keyboard preserved.
6. Discovery: search by name or path; simple status filters; stable default ordering by latest meaningful activity; optional prioritize-attention. No unexpected reordering during normal interaction.
7. Visual: existing design language; less vertical space; consistent card dimensions; Arabic RTL and English LTR; paths/IDs/code tokens directional-correct; desktop/tablet/mobile; polished, uncluttered.
8. Safety: preserve project data, work records, agent execution, approvals/security, project switching, running services, CLI contracts. No new dependencies unless necessary. Don't modify unrelated Console pages.
9. Verification: focused tests for status/progress semantics, next-action selection, empty/active agent states, pending approvals, card navigation and action menus, search/filter, RTL/LTR, mobile layout, removal safeguards. Run checks; real browser visual verification; screenshots Arabic+English, desktop+mobile.
10. Delivery: implement in existing source; report summary, before/after screenshots, unavailable data/actions, tests and results, local install instructions. Do not commit, push, tag, publish or release. Do not alter the globally installed YallaFlow unless explicitly requested.
