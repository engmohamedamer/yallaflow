# YallaFlow v1.5.2 — Tailwind UI Refinement & First-Time UX Fixes (owner brief, 2026-11-11)

Decision: the existing YallaFlow Console in the repository is the design to keep. Improve it with Tailwind CSS, fix the usability problems found in first-time user testing, without changing its identity. Not a new product design.

1. UI improvements using Tailwind CSS — preserve branding/colors/personality, Flow and work-item representation, working layouts, light/dark, Arabic RTL/English LTR, all features. Improve typography, spacing/hierarchy, buttons/forms/menus/status, task cards and Flow columns, responsive behavior, consistent components, loading/error/success/empty states, accessibility/keyboard. Avoid empty areas, gradients, unnecessary cards, duplicated controls. Progressive Tailwind, reuse design tokens. No React/Preact/other framework. Tailwind build only at development/publish time; installed npm package contains the static assets and needs no build.
2A. Existing project without .yallaflow: detect existing codebase / initialized project / empty folder; present the right action; preview initialization changes; initialize from the Console reusing canonical yallaflow init (safety/rollback); guide into project understanding and approval. No modification of application files without review.
2B. Agent setup: on first open, detect Codex and Claude Code, missing CLIs and adapters; show install/connection status; guided setup or repair; exact install commands shown before execution; explicit approval before installing; never sudo; verify the actual agent connection; Linux and macOS; subscription auth without API keys; preserve Claude Code experimental limitations; compact, integrated, no long wizard.
2C. Mandatory readiness: after adding a project, normal work creation and execution unavailable until essential preparation is complete; derive from Core state; distinguish initialization, understanding/baseline approval, agent readiness when required, optional runtime; show what is missing and the next action; enforce on the server; do not block discovery, onboarding, setup repair, read-only features, recovery; existing approved projects and CLI remain compatible.
3. Navigation: simplify Flow, Work, Agents, Setup & Run, Project, Insights, Worktrees without losing functionality; merge Flow and Work into one Workspace page with a small view switcher, preserving both the visual Flow and the Work List; no sidebar or extra navigation layer.
4. The + in the New column becomes a real Create Work button: opens the existing form, uses the current Core creation workflow, respects readiness, keyboard accessible, works in Arabic and English.
5. Setup & Run: clearly communicate readiness, running services, what needs configuration, start/stop, application links, inspecting and recovering failed services; obvious main action; advanced configuration in expandable sections; guided essential steps in order for initial setup; runtime optional when not needed.
6. Clipboard on macOS: fallback beyond navigator.clipboard.writeText, accurate success/failure messages; investigate redraws interrupting clicks.
7. Redraws: lost clicks, inputs losing focus, form resets, scroll jumps, flicker, unnecessary redraws during polling; targeted fixes within the existing architecture.
8. Rules: inspect repo/tests, reuse, record through YallaFlow, define changes and acceptance criteria, risks; implement incrementally. Do not replace the Console with any prototype; no new framework; do not remove functionality; keep Core workflow semantics, CLI and JSON contracts; local-first and secure; no new risks from install/login actions; backward compatible; test Linux/macOS, ar/en, light/dark, mobile; verify the npm package includes the generated Tailwind assets. No commit/push/tag/publish without explicit approval.
9. Delivery: focused testable changes; per area: original problem, what changed, how verified, remaining limitations; automated tests and browser UI regression tests; before/after screenshots of the existing Console; old projects keep working; existing navigation and deep links do not silently break.
Success: a first-time developer opens the Console, sets up/connects an agent with minimal effort, connects an existing Laravel project without manual init, completes project understanding, sees the project ready, creates a task from the Flow, follows agent execution and verification. Existing users recognize the same YallaFlow, more polished, stable and easier.
