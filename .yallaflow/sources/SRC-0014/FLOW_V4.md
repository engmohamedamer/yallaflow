# YallaFlow · Flow v4: كل مرحلة بتسلّم اللي بعدها

> **التاريخ:** 2026-11-05.
> **النوع:** استكشاف تصميم فقط. لا يوجد كود إنتاج، ولا تغيير في YallaFlow Core ولا في `.yallaflow/`.
> **التشغيل:** `node research/next-gen-console/flow-v4/tools/serve.mjs` ثم افتح http://127.0.0.1:4740/
> **البيانات:** تجريبية. التسليمات المباشرة ونشاط الوكلاء محاكاة. كل زرار يعرض أمر `yallaflow` الحقيقي المقابل له.

## الفكرة: الاسم هو التصميم

**Flow** يعني أن الشغل يسير كسباق تتابع: كل محطة **تستلم** من اللي قبلها، و**تسلّم** حاجة ملموسة للي بعدها. المحطات الخمس هي نفس دورة YallaFlow:

| المحطة | تستلم | تسلّم | المقابل في YallaFlow |
|---|---|---|---|
| **افهم** | الطلب | الفهم والأدلة | discovery، reproduce، evidence |
| **قرّر** | الفهم | القرار والمواصفات | design، spec، root cause، plan، والأسئلة والاعتمادات |
| **نفّذ** | القرار | التغيير | implementation |
| **اتحقّق** | التغيير | الدليل | verification وconvergence (معايير القبول) |
| **افتكر** | الدليل | المعرفة | مراجعة المعرفة وحفظها في ذاكرة المشروع |

كل محطة لها لون ثابت يتكرر في كل مكان: أزرق، ثم بنفسجي، ثم فيروزي، ثم زعفراني، ثم أخضر. المراحل الحقيقية لكل نوع شغل تظهر داخل محطتها، مثل `ROOT_CAUSE` داخل «قرّر» لمشكلة، أو `AC-001…AC-006` داخل «اتحقّق». وإذا كانت المحطة لا تنطبق على نوع الشغل، يظهر ذلك صراحة. مثال: البحث (investigation) لا يغيّر الكود، فتظهر محطة «نفّذ» عنده «مش مطلوبة هنا».

## نسبة الاكتمال: صادقة ومحسوبة

- كل محطة = **20%**.
- المحطة التي خلصت تُحتسب 20%.
- المحطة الحالية تُحتسب بنسبة مراحلها التي خلصت، والمرحلة الجارية تُحتسب بنصفها.
- المحطة التي لا تنطبق تُحتسب كاملة.
- نسبة المشروع هي متوسط نسب الشغل.

النسبة تُحسب من البيانات، ولا يقدّرها نموذج ذكاء اصطناعي. طريقة الحساب مكتوبة تحت كل حلقة، وتظهر أيضًا عند الوقوف عليها.

## الشاشات الثلاث

1. **التدفق (الرئيسية).**
   - حلقة كبيرة بنسبة اكتمال المشروع، وجملة واحدة تلخّص اليوم، و4 أرقام: مستنيك، شغّال، فيه مشكلة، خلص.
   - تحتها **المحطات الخمس متصلة بأنابيب** يجري فيها الضوء في اتجاه القراءة (من اليمين لليسار بالعربي).
   - كل مهمة كارت صغير داخل محطتها، عليه نسبتها.
   - المحطة التي يقف عندها الشغل منتظرًا قرارًا منك تُعلَّم «◆ عنق الزجاجة».
2. **الشغل.** كل مهمة **خط تتابع** من 5 مقاطع تمتلئ بلون محطاتها:
   - المقطع الجاري متحرك؛
   - ◆ تعني «مستنيك» و✕ تعني «فيه مشكلة»؛
   - وفي آخر الخط حلقة النسبة.
3. **مسار المهمة.** خمس محطات كبيرة متصلة. كل محطة تعرض:
   - حالتها؛
   - مسؤولها (Claude أو Codex أو أنت)؛
   - المراحل الحقيقية بداخلها؛
   - ما تسلّمه بالضبط.

   المحطة المنتظرة قرارك فيها السؤال وزرار «جاوب» أو «راجع واعتمد». وتحت المحطات **سجل التسليمات** و**الخطوة الجاية** مع الأمر الحقيقي.

## الحركة المميزة: «عصا التسليم»

لما محطة تخلص:
1. **عصا منوّرة تطير** في قوس من المحطة للمحطة التالية، وعليها عنوان ما تم تسليمه (مثلًا «4 أدلة من كود العمولات»).
2. المحطة التي تستلم **تنبض** بلونها.
3. الكارت **ينزلق** لمكانه الجديد.
4. الحلقة **تعدّ** للنسبة الجديدة.
5. يظهر إشعار «Codex سلّم … لمرحلة قرّر».

عندما تصل مهمة إلى 100%، تظهر احتفالية صغيرة بألوان المحطات الخمس. كل الحركة تتوقف مع `prefers-reduced-motion`.

## جرّب

- **جاوب** على سؤال PF-0007 من «مسار المهمة»: محطة «قرّر» تسلّم قرارك لمحطة «نفّذ»، والنسبة ترتفع من 30% إلى 50%.
- **راجع واعتمد** مواصفات PF-0008.
- **كمّل** شغل PF-0010 الذي توقف.
- **اضغط «＋ شغل جديد»** واكتب عنوانًا: الكارت يدخل من «جديد» ثم يتسلّم لـ«افهم».
- **افتح PF-0008** وشوف تبويب «المرفقات»: الـ BRD والتذكرة والصورة كلها بتتعرض.
- **ارفع صورة أو PDF** من «＋ شغل جديد»، وافتحه من صفحة المهمة.
- **استنى أول تحديث مباشر:** PF-0013 بيرجع من «اتحقّق» لـ«نفّذ».
- **اسأل الشات** (مساعد YallaFlow يرد من السجلات بدون ذكاء اصطناعي):
  - «إيه اللي واقف؟»
  - «فين عنق الزجاجة؟»
  - «كام في المية خلص؟»
  - «ابدأ ميزة جديدة»
- **اترك شاشة التدفق مفتوحة** دقيقة: التسليمات المباشرة تحدث وحدها (محاكاة).
- **بدّل** بين العربي والإنجليزي، والفاتح والداكن.

## الإضافات (الجولة 2): بوابة «جديد» وخط «خلص»

التدفق صار له **بداية ونهاية** واضحتين: **جديد ← افهم ← قرّر ← نفّذ ← اتحقّق ← افتكر ← خلص**.

- **بوابة «جديد»** (أول عمود). منها يدخل الشغل، ومعها زرار «＋ شغل جديد» في الشريط العلوي.
  - النافذة تسأل عن:
    - النوع، بكلام بسيط (ميزة، مشكلة، بحث، تعديل، إعادة هيكلة، إصدار)؛
    - العنوان؛
    - الوصف؛
    - الملفات المرفقة (BRD أو تذكرة أو صورة)؛
    - الوكيل؛
    - والحجم تحت «متقدم».
  - تعرض الأمر الحقيقي وهو يُكتب، مثل `yallaflow feature "…" --scope bounded` و`yallaflow intake add …`.
  - ترفض المجموعات التي يرفضها YallaFlow، مثل `spike` مع ميزة.
- **دخول الشغل:** الكارت يظهر في «جديد»، وبعدها بثانية ونصف تطير **عصا التسليم** إلى «افهم» ويبدأ الوكيل.
- **خط «خلص»** (آخر عمود). لما «افتكر» تسلّم المعرفة، تطير العصا لخط «خلص» وتظهر الاحتفالية. كل كارت هناك يعرض 100%، ومعرّفه، وملخص الدليل.
- **أنابيب حقيقية بين الأعمدة.** تُقاس من مواضع الأعمدة في الصفحة، ويجري فيها الضوء في اتجاه القراءة.
- **مسار المهمة:** فيه عقدة «الطلب» في أوله، وعقدة «خلص» في آخره.
- **نوع البحث:** المحطة التي لا تنطبق («نفّذ») تُعلَّم «مش مطلوبة»، والعصا تتخطاها.

## الإضافات (الجولة 3): التفاصيل والمرفقات، والتحسينات العشرة

### عرض التفاصيل
في صفحة كل مهمة، تحت المحطات، فيه لوحة **تفاصيل** بخمس تبويبات:

| التبويب | فيه إيه |
|---|---|
| **الطلب** | الطلب كامل بفقراته ونقاطه. لو طويل، بيظهر مختصر وتحته «اقرأ الطلب كله». ومعاه: مين طلبه، والنوع، والوكيل، وعدد المرفقات. |
| **المرفقات** | كارت لكل ملف (BRD، تذكرة، صورة، جدول، لوج) فيه الحجم ورقم المصدر `SRC-####`، والمتطلبات اللي اتبنت عليه، زي «اتستخدم في REQ-002». |
| **معايير القبول** | كل `AC-###` وحالته (متحقق، فشل، لسه)، والمتطلب اللي جاي منه، والدليل `V-###`. |
| **الأسئلة والقرارات** | كل سؤال وإجابته. السؤال المفتوح جنبه زرار «جاوب». |
| **التفاصيل التقنية** | مجلد الشغل، والمرحلة الحالية، والمصادر، والأوامر. |

**معاينة المرفق:** الضغط على أي ملف بيفتح لوحة جانبية.
- الصورة بتظهر نفسها.
- الـ PDF بيتعرض بصفحاته.
- التذكرة بتظهر ككارت، وعليها تنبيه إن محتواها بيانات بنقراها كمتطلب، مش تعليمات.
- الجدول بيظهر كجدول، واللوج كنص.
- تحت كل معاينة الأمر الحقيقي `yallaflow source show SRC-#### --content`.

الملفات اللي بترفعها من «شغل جديد» بتتعرض فعلًا، صور وPDF، من غير ما تترفع لأي مكان. الملفات بتتقري محليًا في المتصفح بس.

**التسليمات بتتفتح:** أي تسليم في محطة خلصت، زي «3 متطلبات من التذكرة»، بقى رابط. بيفتح اللي اتسلّم بالظبط: المتطلبات، أو الأدلة، أو الملفات اللي اتغيرت، أو المعرفة.

### التحسينات العشرة
1. **الرجوع للتصليح.** لما التحقق يفشل، عصا حمرا بترجع لـ«نفّذ» ومعاها السبب. الكارت بيتعلّم «↩ رجع للتصليح»، والرجوع بيتسجل بالأحمر في سجل التسليمات. النسبة بتنزل بصدق.
2. **عمر الكارت.** كل كارت عليه من إمتى هو في المحطة. لو مستني قرارًا أو متوقفًا أكتر من 3 ساعات، بيتعلّم بلون كهرماني.
3. **التسليمات بتتفتح.** اتشرحت فوق.
4. **فلترة وتجميع.** بحث بالاسم أو الرقم، وفلترة بالحالة، والوكيل، والنوع. المحطة بتعرض 4 كروت بس، وتحتها «+N كمان».
5. **«من آخر مرة كنت هنا».** ملخص في أول الصفحة، وكل سطر فيه السجل اللي جاي منه.
6. **صفحة الوكلاء.** أنت، وClaude Code، وCodex: كل واحد شغّال على إيه، وعدد تسليماته ورجوعاته.
7. **التنبيهات.** جرس عليه عدد التنبيهات، وبينبّه بس للي محتاج إنسان: سؤال، مراجعة، فشل، أو شغل خلص.
8. **أكتر من مشروع.** من اسم المشروع فوق، كل مشروع ليه حلقة نسبته وتوزيع شغله على المحطات.
9. **صفحة الأرقام.**
   - متوسط الوقت في كل محطة.
   - أبطأ محطة، والسبب: كام في المية من وقتها مستني قرار.
   - اللي خلص كل يوم.
   - كل رسم عليه تلميح لما تقف عليه، وجنبه نسخة كجدول.
10. **الموبايل رأسي.** التدفق على الموبايل بيمشي من فوق لتحت، وبين المحطات خط بيجري.

## الإضافات (الجولة 4): الفريق، كذا وكيل بالتوازي

تبويب **«الفريق»** فيه خط لكل وكيل شغّال. كل خط عليه:
- **مين الوكيل** (Claude Code أو Codex، ولو فيه أكتر من نسخة من نفس الوكيل: ‎#2 و‎#3)، و**نسخته من المشروع** (`git worktree`)، و**الفرع** بتاعه.
- **الشغل اللي ماسكه**: خط صغير بالمحطات الخمسة، المحطة الحالية فيه بتنبض، وجنبه النسبة والحالة.
- **بيعمل إيه دلوقتي**: سطر بيتحدّث لوحده.
- **الملفات اللي بيعدّلها.** لو الشغل بحث، بيظهر «قراءة بس».
- **🔒 القفل**: بيورّي مين بيكتب في `.yallaflow` في اللحظة دي. اتنين ما يكتبوش في نفس الوقت.

**التعارض:** لو وكيلين بيعدّلوا نفس الملف، بيظهر تحذير أحمر فوق الخطوط ومعاه اختيارين:
- «خلّي الوكيل التاني يستنى»؛
- أو «كمّلوا، هحلّه وقت الدمج».

**＋ شغّل وكيل:** تختار الوكيل والشغلانة. الشغلانة اللي وكيل تاني ماسكها مقفولة، واللي مستنية قرارك عليها علامة. بيظهر الأمرين الحقيقيين:

```
git worktree add ../northwind-pf0011 -b release/pf0011
cd ../northwind-pf0011 && claude "yallaflow resume PF-0011"
```

بعد كده بيظهر خط جديد بيمر بالخطوات دي: «بيجهّز النسخة» ← «بيقرا ذاكرة المشروع» ← «بدأ الشغل».

**ذاكرة المشروع المشتركة:** لوحة بتوضّح إن الوكيل اللي على فرع جانبي ما بيكتبش في الذاكرة الرئيسية. هو بيجهّز المعرفة بس. ولما إنت تدمج الفرع في git، المعرفة بتتجمّع على الفرع الرئيسي بـ `yallaflow shared integrate`.

**القواعد اللي بتخلّي ده آمن:**
1. كل وكيل في نسخة منفصلة وعلى فرع لوحده.
2. الشغلانة الواحدة ليها وكيل واحد بس.
3. كتابة واحدة في `.yallaflow` في كل لحظة. **ده محتاج قفل في Core، ولسه مش موجود.**
4. لو اتنين لمسوا نفس الملف، بيظهر تحذير قبل الدمج.
5. الدمج في git قرارك إنت.

| الجزء | يحتاج |
|---|---|
| مين ماسك إيه، والمرحلة، والنسبة | ✓ Core (حالة كل نسخة في `.yallaflow/local/`) + ⇄ Console API |
| الملفات اللي اتعدّلت واكتشاف التعارض | ⇄ Console API (`git -C <نسخة> diff --name-only`، قراءة بس) |
| القفل | Core 1.2 (`.yallaflow/local/lock`)، لسه |
| تشغيل الوكيل وإيقافه، و«بيعمل إيه دلوقتي» لحظة بلحظة | ◎ Agent Runtime، لسه |

## ما يحتاجه كل تفاعل

| التفاعل | يحتاج |
|---|---|
| المحطات والنسب والتسليمات من الملفات | ✓ Core (الـ checkpoints والمراحل موجودة) + ⇄ Console API |
| جاوب، اعتمد، ابدأ شغل | ✓ Core (الأوامر موجودة) + ⇄ Console API |
| مساعد YallaFlow في الشات | ⇄ Console API، بدون ذكاء اصطناعي |
| الطلب والمرفقات والمعايير والأسئلة والتسليمات | ✓ Core (`work.md`، `sources/`، `requirements.yaml`، `convergence.yaml`، `questions.yaml`، `progress.yaml`) + ⇄ Console API |
| معاينة المرفقات | ✓ Core يحفظ الأصل والنص المستخرج + ⇄ Console API لعرضها |
| الرجوع للتصليح والوقت في المحطة والأرقام | ✓ Core (المراجعات والـ checkpoints بأوقاتها) + ⇄ حساب في الكونسول |
| الفلترة، و«من آخر مرة»، والتنبيهات، وتعدد المشاريع | ⇄ Console API فقط |
| نشاط الوكيل اللحظي، و«كمّل» الجلسة، والشات مع Claude أو Codex، وصفحة الوكلاء المباشرة | ◎ Agent Runtime (غير موجود اليوم) |

## ملاحظات أمانة

- **التقييم:** لم يُختبر التصميم مع مستخدمين حقيقيين.
- **المتصفح:** اختُبر على Chromium فقط، على شاشة 1440 وعلى الموبايل (390): بدون أي أخطاء، وبدون تمرير أفقي للصفحة.
- **المراحل:** التحويل من المراحل الحقيقية إلى المحطات الخمس **للعرض فقط**، ويبقى اسم المرحلة الحقيقي ظاهرًا.
- **ملخصات التسليم** في الإنتاج تأتي من ملخّص كل checkpoint (`progress.yaml`) ومن الأدلة المسجلة.
