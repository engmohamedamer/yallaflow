YallaFlow بيدّي وكيل البرمجة بتاعك ذاكرة متراجعة للكود بتاعك، وطريقة شغل على قد كل طلب، وأدلة قبل ما أي حاجة تتقال إنها خلصت.

npm install -g yallaflow

الكونسول

مشاريعك، وطلباتك، والأبلكيشن وهو شغّال، في شاشة واحدة

yallaflow console بيفتح أبلكيشن ويب على جهازك، بالعربي أو الإنجليزي، فاتح أو غامق. اكتب طلباتك بكلامك، وتابع كل طلب لحد ما يخلص متثبت، وشغّل الأبلكيشن بتاعك بزرار واحد. دي شاشات حقيقية.

الجديد في 1.4.1

اضبط المشروع مرة واحدة، وبعدها دوس «شغّل» وبس.

تشغيل الأبلكيشن بقى جزء من الكونسول، حتى لو الـDocker stack في فولدر فوق المشروع، ومعاه قاعدة البيانات ومواقع *.localhost.

  1. 1

    اسأل الوكيل المشروع بيشتغل إزاي

    الوكيل بيقرا الإعدادات الحقيقية (Compose، وvhosts، والفولدرات اللي فوق المشروع)، ويقترح الخدمات وترتيب التشغيل والمنافذ والروابط، ومع كل حاجة درجة تأكدها ودليلها. تحقيقه للقراءة بس، وعمره ما بيفتح .env.

  2. 2

    راجع ووثّق، مرة واحدة

    بتشوف بالظبط الأمر والفولدر والملفات اللي التوثيق مربوط بيها، وبعدها بتكتب اسم الخدمة. أي تغيير بعد كده بيلغي التوثيق لحد ما تراجعها تاني.

  3. 3

    ▶ شغّل المشروع

    صفحة الإعداد بتبقى لوحة التشغيل: حالة واحدة، وشغّل ووقّف، والتطبيقات اللي تفتحها، وسطر لكل خدمة بسجلّها. الخدمات بتشتغل بترتيب الاعتماد.

  • مفيش حاجة بتشتغل لوحدها
  • الـstack المشترك عمره ما بيتوقف بالغلط
  • مفيش أسرار في الخطط ولا السجلات

ليه YallaFlow

السياق اللي ناقص وكيلك

إنت بتوصف المطلوب. YallaFlow بيحفظ الحالة الدايمة حوالين الوكيل، والوكيل بيفكّر ويكتب الكود.

ذاكرة دايمة للمشروع

فهم متراجع للكود بتاعك، بأدلة، وبينبّهك لما الأدلة دي تتغيّر.

شغل على قد الطلب

الباج، والفيتشر، والتحقيق، كل واحد ليه دورة على قد حجمه. الصغير بيفضل خفيف.

تسليم متثبت

مفيش حاجة بتخلص من غير دليل تحقّق جديد، ومتقارن باللي اتطلب.

استمرارية الوكيل

كل جلسة جديدة وكل زميل بيبدأ من الفهم المعتمد واللي اتسجّل من شغل.

بيشتغل إزاي

من الطلب لنتيجة متسجّلة

كل يوم إنت بتكلّم وكيلك. YallaFlow نفسه مابيكلّمش أي موديل ذكاء اصطناعي، ومابيبعتش أي بيانات تتبّع.

  1. جهّز المشروع

    yallaflow init بيربط Claude Code وCodex، وملفات التعليمات الموجودة بتفضل زي ما هي.

  2. اوصف الشغل

    اطلب من وكيلك بكلام عادي. مش محتاج تقول «استخدم YallaFlow».

  3. وافق مرة واحدة المشاريع القايمة

    الوكيل بيرسم خريطة الكود من غير ما يغيّر حاجة، ويوريك لقى إيه وفاته إيه، ويستنى موافقتك Approve.

  4. وجّه وابني

    الطلب بياخد طريقة الشغل المناسبة، من تصليح سريع لخطة متراجعة.

  5. اتحقّق وافتكر

    الدليل الأول. واللي اتعلّم بيبقى معرفة متراجعة للمشروع.

بعد الموافقة الأولى، طلبك الأصلي بيكمل لوحده. اقرا الدليل الكامل (بالإنجليزي).

بيشتغل على مشروع جديد أو قايم، ومحتاج Node.js ≥ 20.16.0. سطّبه كأداة، وعمره ما يتسطّب كـdependency في الأبلكيشن بتاعك.

  1. npm install -g yallaflow
  2. yallaflow init
  3. describe the work · اوصف الشغل

Terminalسطّب مرة، واربط كل مشروع

$ npm install -g yallaflow
$ cd your-project
$ yallaflow init
$ yallaflow console      # optional: open it in your browser · اختياري

بتبدأ من الصفر؟ استخدم كل المشاريع ← مشروع جديد في الكونسول بدل init.

Promptوبعدها اطلب من Claude Code أو Codex

  • صلّح إجماليات الفواتير.
  • ابني منصة استبيان مجهول للموظفين.

دي رسايل لوكيلك، مش أوامر ترمينال.

Upgradeلما تنزل نسخة جديدة، إنت اللي بتقرر إمتى تترقّى

  1. npm install -g yallaflow@latest
  2. yallaflow upgrade status
  3. yallaflow agent refresh
  4. yallaflow doctor
  5. restart the console · أعد تشغيل الكونسول
$ npm install -g yallaflow@latest   # or an exact version: yallaflow@1.4.1
$ yallaflow upgrade status          # read-only: what, if anything, needs attention
$ yallaflow agent refresh           # only if the agent contract is reported outdated
$ yallaflow doctor

YallaFlow عمره ما بيحدّث نفسه. شغلك وذاكرة المشروع والمصادر بتفضل زي ما هي. أعد تشغيل yallaflow console علشان المتصفح يحمّل النسخة الجديدة. التفاصيل (بالإنجليزي)
