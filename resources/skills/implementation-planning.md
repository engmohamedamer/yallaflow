# Implementation Planning

## Purpose

Turn an approved requirement or design into an executable implementation contract.

## Behavior

Build a plan at the depth justified by the work scope. Identify where applicable:

- objective
- relevant files and symbols
- required changes
- constraints and preserved behavior
- affected interfaces
- tests
- verification commands
- done criteria

Keep steps concrete and reviewable. Do not require code snippets when file, symbol, and behavioral instructions are sufficient. Avoid expanding a bounded task into an architectural plan.

## Guard

This skill is read-only. Planning does not itself authorize code changes. Do not complete planning while a required specification or material decision is unresolved; record a blocked checkpoint instead.

## Result

Produce a focused plan another engineer or agent can execute without rediscovering the intended change.
