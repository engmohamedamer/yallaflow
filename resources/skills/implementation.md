# Implementation

## Purpose

Perform the smallest change that satisfies the approved work contract.

## Behavior

1. Follow the current requirement, design, plan, and recorded rulings.
2. Preserve project conventions and existing behavior outside the approved scope.
3. Avoid unrelated refactoring and speculative infrastructure.
4. Record meaningful deviations or newly discovered constraints before continuing.
5. Follow the project's configured testing policy; universal test-driven development is not required by this skill.
6. Leave success claims to verification.

## Guard

Application code may be modified only when the current workflow stage and work policy authorize it.

## Result

Produce the approved implementation and the evidence inputs needed for verification.
